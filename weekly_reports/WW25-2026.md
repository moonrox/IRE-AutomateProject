# WW25 — Week of Jun 14–Jun 20, 2026
John Monroe | Infrastructure Reliability Engineering

## Summary

This week's focus was production hardening of the IRE KPI server and
IRE-Observability monitor. The biggest change was migrating the KPI server
from direct port exposure to an IIS reverse proxy on the corp hostname
`ire-dashboard.amr.corp.intel.com:443`, with TLS termination, security
headers, and Windows Task Scheduler-based process management. A daily
automated data sync was also stood up. IRE-Observability was updated to
run as a sub-path (`/monitor/`) behind the same IIS site.

## Activity by Project

### ire-kpi-graphql — KPI Server

---

#### 1. IIS Reverse Proxy Migration  *(ops/setup_iis_reverse_proxy.ps1)*

Moved the KPI server off direct port access onto a proper Windows IIS
site with TLS and a corporate hostname.

**What changed:**
- New IIS site `IREKpiHttps` bound to `ire-dashboard.amr.corp.intel.com:443`
- IIS ARR (Application Request Routing) proxies all traffic to FastAPI on
  `https://127.0.0.1:8766`
- `/monitor/` sub-path routes to IRE-Observability on `http://127.0.0.1:8000`
- `web.config` generated with URL Rewrite rules (3 rules: monitor redirect,
  monitor proxy, main proxy)
- X-Forwarded-Proto/Host/For/Prefix headers injected so FastAPI sees correct
  HTTPS scheme behind the proxy
- `ops/remove_iis_reverse_proxy.ps1` — rollback script included
- `web.config.bak` auto-created on each reconfigure run

**Why it matters:**
Users can now access the dashboard at `https://ire-dashboard.amr.corp.intel.com`
instead of `http://hostname:8765`. TLS is handled by IIS — FastAPI keeps
running on an internal port only.

---

#### 2. Windows Task Scheduler Service  *(ops/install_service.ps1)*

Replaced the old Windows service approach with a Task Scheduler task.

**What changed:**
- `IREKpiWebsite` scheduled task runs `start.py` as SYSTEM at system startup
- Old Windows service (`sc.exe delete`) cleaned up automatically on install
- Restart policy: 3 retries, 1-minute interval, unlimited runtime
- `ops/restart_service.ps1` — health-check-aware restart:
  - Drains the port (waits up to 15s for port release)
  - Starts the task
  - Polls `/health` for up to 30s before reporting success/failure
- `ops/uninstall_service.ps1` — clean removal script

---

#### 3. Production Launcher  *(start.py)*

New production entry point that handles environment setup before handing
off to `server.py`.

**What changed:**
- **PFX certificate support** — reads `SSL_PFX_FILE` / `SSL_PFX_PASSWORD`
  from `.env`, extracts cert + key PEM to a temp dir at startup, sets
  `SSL_CERTFILE` / `SSL_KEYFILE` env vars, cleans up on exit via `atexit`
- **Proxy config** — sets `HTTP_PROXY`/`HTTPS_PROXY` defaults; adds
  `NO_PROXY` bypass for `127.0.0.1`, `localhost`, and `*.intel.com`
  (corp endpoints go direct, not through DMZ proxy)
- **venv re-exec guard** — ensures the correct Python interpreter is used
- **Health wait loop** — polls `/api/health` for up to 45s; exits with
  non-zero code if server doesn't come up

---

#### 4. Daily Automated Data Sync  *(ops/daily_sync.ps1 + install_daily_sync.ps1)*

Automated nightly data refresh so the dashboard data stays current without
manual intervention.

**What changed:**
- `IREKpiDailySync` scheduled task runs daily at 1 AM as SYSTEM
- Runs two jobs in sequence:
  1. `backfill_lake.py --current-quarter` — incremental SN change_request fetch
  2. `cmdb_backfill.py` — incremental CMDB service + offering sync
- Timestamped log files written to `logs/daily_sync_YYYY-MM-DD_HH-mm-ss.log`
- Logs pruned automatically after 30 days

#### 5. Server Security Hardening  *(server.py — updated June 5)*

Three new middleware layers added to `server.py`:

| Middleware | What it does |
|---|---|
| `SecurityHeadersMiddleware` | Adds X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, Content-Security-Policy to every response |
| `CaseInsensitiveRedirect` | 301-redirects any URL case variation to canonical form; includes legacy alias `/kpisignal1` → `/SignalReadiness` |
| `IntrospectionBlocker` | Blocks GraphQL `__schema`/`__type` queries when `GRAPHQL_INTROSPECTION=false` — HTTP-level, Strawberry-version agnostic |

#### 7. Data Lake Backfill CLI  *(backfill_lake.py — updated June 8)*

Standalone command-line tool for historical data ingestion (used for initial
load and ad-hoc quarter backfills).

- Async `httpx` with 3-attempt retry per page and 3s backoff
- Page size 500 (up from 200) to reduce SN API round trips
- Skip-existing upsert by `sys_id` — safe to re-run
- Progress printed live to stdout
- Usage: `python backfill_lake.py --all-2025` or `--quarter 2025-Q4`

### IRE-Observability — Availability Monitor

#### IIS Sub-Path Integration  *(run_monitor.py — updated June 8)*

Added `--root-path` CLI argument so the monitor's ASGI app reports correct
URLs when running behind the IIS reverse proxy at `/monitor/`.

**What changed:**
- `--root-path /monitor` argument passed to `uvicorn.run()` as `root_path=`
- IIS URL Rewrite rule strips `/monitor/` prefix before forwarding to port 8000
- `X-Forwarded-Prefix: /monitor` injected by IIS ARR rule
- Monitor is now accessible at `https://ire-dashboard.amr.corp.intel.com/monitor/`
  alongside the KPI server at `/`

## Key Technical Notes

- IIS ARR requires the **URL Rewrite** and **Application Request Routing**
  modules. `setup_iis_reverse_proxy.ps1` warns if Rewrite is missing.
- `preserveHostHeader = True` on the ARR proxy ensures FastAPI's
  `Request.url` reflects the real hostname, not `127.0.0.1`.
- The PFX loader in `start.py` writes PEM files to a `tempfile.mkdtemp()`
  directory and registers an `atexit` handler for cleanup — TLS keys never
  persist on disk after the process exits.
- The daily sync uses `backfill_lake.py --current-quarter` (incremental,
  skips existing sys_ids) so each run is fast and idempotent.
- IRE-Observability `--root-path` flag is only needed when running behind
  a sub-path proxy. Running standalone (`python run_monitor.py`) is unchanged.
